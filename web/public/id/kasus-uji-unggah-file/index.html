Kasus Penggunaan

Kasus uji unggah file, lengkap dengan file untuk menjalankannya

Daftar periksa kasus uji untuk unggah file, dari batas ukuran sampai nama file yang mencoba keluar dari foldernya. Setiap kasus menyebut file yang mengujinya dan apa yang harus dilakukan sistem Anda terhadapnya, sehingga daftar ini bisa dijalankan, bukan hanya dibaca.

Seluruh daftar dalam satu perintah

tfg generate --preset upload-validation --limit 10mb --allow jpg,png,pdf --out ./upload menulis file untuk hampir setiap kasus di bawah, beserta manifes yang menyatakan apa yang harus terjadi pada masing-masing. Isi batas dan tipe yang dinyatakan formulir Anda.

accept berarti sistem Anda harus menerima file, dan reject berarti harus menolaknya dengan pesan yang jelas. unspecified berarti kedua jawaban bisa benar, jadi catat jawaban mana yang dipilih sistem Anda, lalu periksa bahwa sistem melakukannya setiap kali. Kata setelah hasil adalah alasan yang diberikan manifes.

Ukuran

Apakah batas ukuran ditegakkan di tempat batas itu dinyatakan?

Kasus ujiFileDiharapkan
Satu byte di bawah batas10mb_under_1b.jpgaccept
Tepat di batas10mb_at_limit.jpgaccept
Satu byte di atas batas10mb_over_1b.jpgreject size_limit
Dua kali batas, untuk melihat bahwa server berhenti membaca lebih awal alih-alih memuat semuanya ke memori10mb_far_over_2x.jpgreject size_limit
File kosong berukuran 0 byteempty.jpgunspecified size_zero

Dua kasus yang paling sering membuat batas keliru adalah batas yang hanya diperiksa di browser, dan batas yang dihitung dalam MB padahal kode menghitung MiB. Preset size-boundaries menaruh file di setiap jarak dari batas yang Anda pilih, satu byte, satu kilobyte, dan satu megabyte di kedua sisi.

Tipe

Apakah formulir menerima tipe yang seharusnya dan menolak sisanya?

Kasus ujiFileDiharapkan
Setiap tipe yang diterima formulir, sebagai file asli bertipe ituallowed_jpg.jpg, allowed_png.png, allowed_pdf.pdfaccept
Tipe yang tidak diterima formulirdenied.svg, denied.html, denied.exe, denied.shreject extension_rule
Ekstensi menyebut satu tipe, tetapi isinya tipe lain, misalnya PDF bernama .jpgpdf_as_jpg.jpg, png_as_pdf.pdf, jpg_as_png.pngreject mime_mismatch
Dua ekstensi, yang terakhir tidak diizinkaninvoice.jpg.exereject extension_rule
Tanpa ekstensi sama sekaliinvoiceunspecified extension_rule
Ekstensi dalam huruf kapitalPHOTO.JPGunspecified extension_rule

File SVG atau HTML yang dianggap gambar atau teks biasa adalah cara meloloskan skrip lewat formulir. Karena itu keduanya ada di daftar tipe yang harus ditolak, kecuali formulir Anda memang dimaksudkan untuk menerimanya.

Isi

Apakah sistem membuka file, atau hanya melihat namanya?

Kasus ujiFileDiharapkan
File yang terpotong, seperti yang ditinggalkan unggahan yang terputuscorrupt-truncate.pdfreject content_malformed
File yang byte pertamanya nol, sehingga tidak ada yang menyatakan file apa itucorrupt-zero-head.pngreject content_malformed
File terkecil yang diizinkan suatu format, valid dan sangat keciltfg generate --preset empty-and-minimalaccept

File yang hanya punya nama dan ukuran yang benar lolos dari setiap pemeriksaan yang tidak pernah membukanya. Contoh file rusak tersedia dalam PDF, Word, Excel, PowerPoint, JPG, PNG, MP4, dan ZIP, dan file uji yang rusak menjelaskan cara membuatnya dalam format apa pun dan ukuran berapa pun.

Nama

Apakah file kembali dengan nama yang diberikan padanya?

Kasus ujiFileDiharapkan
Spasi dan tanda kurungmy report (final) v2.jpgaccept
Huruf di luar ASCII dan emojiwiadomość_日本語_🎉.jpgunspecified filename_invalid
Nama lebih dari 200 karakteraaa...aaa.jpgunspecified filename_too_long
Nama yang memanjat keluar dari foldernya, ../ atau ..\climbing_name.jpg, diunggah sebagai ../tfg_climbed_out.jpgunspecified filename_traversal
Path absolut, di Linux atau Windowsabsolute_name.jpg, diunggah sebagai /tmp/tfg_climbed_out.jpgunspecified filename_traversal

Path di dalam nama tidak bisa disimpan ke disk, jadi file memakai nama biasa dan manifes menyatakan dengan nama apa file itu diunggah. Menerima file dan hanya menyimpan bagian terakhir namanya adalah jawaban yang baik. Menulisnya di luar folder unggahan adalah cacat yang dicari kasus ini. Preset filename-handling punya jauh lebih banyak nama: huruf yang mirip, karakter tak terlihat, nama yang dicadangkan Windows, dan panjang yang dihitung dalam byte.

Dalam tes

Menjalankan daftar ini sebagai tes

Manifes memuat hasil yang diharapkan untuk setiap file dan nama untuk mengunggahnya, jadi satu loop menjalankan seluruh daftar: 

import json, os

directory = "upload"
manifest = json.load(open(os.path.join(directory, "manifest.json")))

for entry in manifest["files"]:
    outcome = entry["expected"]["outcome"]
    if outcome == "unspecified":
        continue
    name = entry.get("send_as", entry["name"])
    response = upload(os.path.join(directory, entry["path"]), name)
    assert response.ok == (outcome == "accept"), name

File yang ditandai unspecified dilewati di sini, karena jawabannya adalah kebijakan Anda sendiri. Putuskan, tulis ke dalam resep dengan expected, dan loop akan memeriksanya juga. File uji di CI menjalankan ini di pipeline.
