Documentación

Comprobar un archivo comprimido antes de descomprimirlo y verificar sumas de comprobación

Además del generador, tfg tiene pequeñas herramientas para archivos que ya tienes: si es seguro descomprimir un archivo comprimido, y si un archivo o una carpeta entera sigue siendo lo que dice su suma de comprobación. Se ejecutan en tu máquina, sin subir nada y sin cuenta.

La respuesta corta

tfg tool archive-scan download.zip lee el archivo comprimido sin descomprimir nada y termina con el código 0 si es seguro, o con 7 y una lista de lo que ha encontrado. tfg tool checksum setup.exe --expected <sum> dice si un archivo coincide con la suma que te dio una página de descarga.

Qué hay

¿Qué herramientas hay?

Esta es la lista que imprime el programa, leída de él al construir esta página. tfg tool list imprime la misma, y tfg tool show <id> dice qué admite cada una. Cada herramienta está también en la pantalla Tools de la ventana, con los mismos ajustes.

Archivos comprimidos

¿Es seguro descomprimir este archivo comprimido? Zip slip y zip bombs

archive-scan mira dentro de un archivo ZIP, TAR, TAR.GZ o gzip sin escribir nada en el disco y dice si descomprimirlo es seguro. Informa de:

  • una entrada que se escribiría fuera de la carpeta, la trampa conocida como zip slip
  • un enlace, un dispositivo, o dos nombres que acabarían en un mismo archivo
  • un nombre que un sistema no puede escribir
  • una entrada hecha para explotar al descomprimirla, la trampa conocida como zip bomb
  • una entrada dañada

Los archivos comprimidos que hay dentro, como un ZIP dentro de un ZIP o un DOCX dentro de un TAR, se leen de la misma forma, en memoria, hasta 16 niveles de profundidad. Una trampa en uno de ellos es una trampa en el conjunto, porque un programa que lo descomprime todo también los descomprime a ellos. 

tfg tool archive-scan upload.zip
tfg tool archive-scan backup.tar.gz --unpacked_limit 500mb

--unpacked_limit también informa de un archivo comprimido que, una vez descomprimido, ocupa más de lo que permites. Si es seguro, termina con el código 0, y si encuentra algo, con 7, así que un pipeline puede detenerse ahí.

Un archivo

¿Es este archivo el que dice ser?

checksum calcula la suma de comprobación de un archivo y, si le das una con la que compararla, dice si coinciden. Admite md5, sha1, sha256, sha512 y crc32, sha256 si no pides otra, y reconoce por su longitud cuál le has dado. 

tfg tool checksum installer.msi
tfg tool checksum installer.msi --expected 9f86d081884c7d659a2feaa0c55ad015a3bf4f1b2b0b822cd15d6c15b0f00a08

Una suma que no coincide termina con el código 7. Responde a la misma pregunta que Get-FileHash en Windows o sha256sum en Linux, pero hace la comparación por ti.

Una carpeta entera

¿Ha cambiado algo en esta carpeta?

checksum-write escribe la suma de comprobación de cada archivo de una carpeta en un SHA256SUMS junto a ellos, con los mismos bytes que escribe sha256sum, y nunca encima de uno que ya exista. checksum-check comprueba después cada archivo que lista SHA256SUMS. 

tfg tool checksum-write ./fixtures
tfg tool checksum-check ./fixtures/SHA256SUMS

Los archivos que no lista no se miran, igual que con sha256sum -c, y una ruta que sale de la carpeta se rechaza en lugar de leerse. Los archivos de ejemplo traen un SHA256SUMS que puedes comprobar así.
