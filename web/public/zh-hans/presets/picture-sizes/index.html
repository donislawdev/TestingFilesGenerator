预设

图片尺寸

我的系统能接受屏幕和平台所用尺寸的图片吗？

picture-sizes 预设用一条命令为这个问题构建出整套真实测试文件，并在旁边放一个 manifest.json，说明你的系统应如何响应每个文件。以下所有内容都按此版本的默认值从程序中读取。

它通常能发现什么？

  • 按一种形状设定的宽度或高度上限拒绝了另一种形状，例如宽 1584 px 的个人资料背景
  • 代码以为是横向图片，来的却是纵向图片，于是缩略图被裁切或压扁
  • 高度为奇数的图片，例如 1200 x 627，被只接受偶数尺寸的步骤拒绝
  • 文件本身很小，生成缩略图时却耗尽时间或内存的 4K 图片

集合里有什么？

使用默认值时，如 tfg preset show picture-sizes 所报告的：

文件数21
其配方中的 target 数21
总大小4 178 420 B
格式jpg

以及该集合的清单对你的系统有何预期：

预期含义文件数
accept你的系统应该接受这个文件。21

你可以更改什么？

设置接受默认值作用
--groups 以逗号分隔的组名，或 all all 集合包含哪些尺寸：screens 表示屏幕尺寸，avatars 表示头像，social 表示封面、横幅、帖子和缩略图。填 all 表示全部。
--content placeholder, test test 图片显示什么。测试图案用于检查文件如何被读取。占位图是中间有文字的纯色图片，用于在真实图片出现之前排版页面。
--format 格式页面中的格式 id jpg 集合中每个文件的格式。它是工具本身的参数，预设只是给它一个默认值。

如何运行？

查看集合的开销、构建它，或取出它的配方来编辑：

tfg preset show picture-sizes
tfg generate --preset picture-sizes --out ./picture-sizes
tfg preset eject picture-sizes > picture-sizes.yaml

也可以在你自己的配方中基于它构建，放在测试旁边：

version: 1
extends: preset:picture-sizes
