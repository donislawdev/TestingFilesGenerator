Format settings

Every setting each format takes, with the values it accepts, its default and what it changes in the file. The list is read from the program when this page is built, in the program's own words: tfg formats <id> prints the same for one format.

How to give a setting

On the command line, --set takes one setting and repeats. In a recipe, the settings go under properties:

tfg generate --format pdf --size 1mb --set pages=20 --set page_size=letter --out ./pdf
targets:
  - id: report
    format: pdf
    size: 1mb
    properties:
      pages: 20
      page_size: letter

A setting left out takes its default. A value outside what the setting accepts is refused before anything is written, with the values that would work. Some settings also limit the smallest size a file can be, and a size below it is refused with the size that would work. The list of formats themselves, with the smallest file of each, is on Formats.

eml Email message

SettingAcceptsDefaultWhat it does
body alternative, html, plain plain Which text the message carries. With plain text and HTML the same words go in both, and a mail program shows one of them.
layout newsletter, simple simple How the text is laid out. simple is the text alone. newsletter wraps it the way a mailing list does - a title, a Read more button and a footer with an unsubscribe link, in a table 600 pixels wide styled both by a style sheet and by style attributes, and the plain text writes out the addresses the HTML puts behind its links. It adds List-Id, List-Unsubscribe and List-Unsubscribe-Post, by which mail systems tell bulk mail apart, and the manifest gives the unsubscribe address as unsubscribe_url. The message has no DKIM signature, so a mail program that follows RFC 8058 offers no one-click unsubscribe. Messages inside stay simple.
text_encoding 7bit, 8bit, base64, quoted-printable 7bit How the text is written. 7bit keeps it to plain ASCII. quoted-printable, 8bit and base64 add a line in Polish, and in Japanese when the charset is utf-8, because that is what they are for. quoted-printable spells those letters as =C5=BC, 8bit writes them as they are, and base64 writes the whole text in base64. To reach every size base64 ends the text with empty lines, and with crlf an odd size gives the Message-ID one more digit.
charset iso-8859-2, utf-8, windows-1250 utf-8 The character set of the text when the text encoding is not 7bit. iso-8859-2 and windows-1250 hold Polish and no Japanese, and they write ą, ś and ź as different bytes, so a program that takes one for the other shows the wrong letters. MimeKit with no code page provider registered tries UTF-8 and then Latin-1, which shows the Polish letters of both wrong, and reads them right once one is. Go's standard library converts no character set at all. With 7bit the text is plain ASCII and says us-ascii, whatever this is set to.
headers ascii, encoded, utf8 ascii Whether the subject, the names of the sender and the recipient and the names of attached files carry letters outside ASCII, and how. encoded writes them the way RFC 2047 and RFC 2231 say. utf8 writes them as they are (RFC 6532), and Python's email package reads that and reports a defect in the From and To lines.
recipients 1 - 100000 1 How many addresses the To line carries, each on a line of its own. mailparser refuses a header of more than 1 MiB, which about 33 800 addresses reach with crlf and 34 900 with lf, and Python 3.14's email package takes minutes over tens of thousands of them.
line_endings crlf, lf crlf How every line of the file ends. The standard is crlf. Python, MimeKit, mailparser and Go's standard library all read lf too, so the difference shows in programs that split the lines themselves.
attachments 0 - 10000 0 How many files the message carries. When the files are not all alike, describe each kind on its own instead - with Add files inside on Several batches, or contains in a recipe. mailparser refuses a message of more than 1000 MIME entities, and the manifest gives this one's count as mime_entities.
attachment_format the id of a format, such as png or csv txt The format of the attached files. eml attaches a message as it is, the way mail is forwarded, with no base64 around it.
attachment_size a size such as 2mb 8kb How big each attached file is. The message grows by about a third more, because attached files travel in base64.
filename_style both, content-type, none, rfc2047, rfc2231 rfc2231 How the names of attached files and pictures are written. rfc2231 is the standard way. rfc2047 is the encoded form RFC 2047 forbids inside a name, and many readers decode it anyway. both writes the two, and content-type puts the name only where old mail programs looked for it. none writes no name at all, and a program that needs one has to make one up - Thunderbird 157 calls them Part 1.2, Part 1.3 and so on. Go's standard library reads no name from content-type and the encoded text itself from rfc2047. Unless the headers are encoded, a name is written as it is and only where it goes changes, so rfc2047 and both write the same bytes.
message_depth 1 - 2000 1 How many messages deep the message goes. 1 is a message alone. 2 carries a forwarded message as an attachment, and each step adds one more inside the last, the smallest message each can be. Python 3.14's email package runs out of recursion at around 490, and MimeKit stops taking them apart past 513 without a word. Thunderbird 157 shows up to 32 in full. Past that the 32nd message inside shows only its headers and nothing under it appears, without a word.
inline 0 - 10000 0 How many pictures the text shows. With html and alternative each one sits beside the HTML and the HTML points at it through cid:. With plain there is no HTML to point from, so they travel after the text as pictures to show inline. mailparser lists them among the attachments, and so does Python's email package when the HTML is alone. MimeKit never does.
inline_format the id of a picture format, such as png or jpg png The format of the pictures. Any format whose files are pictures, such as png, jpg or gif.
inline_size a size such as 2mb 8kb How big each picture is. Like an attached file it travels in base64, about a third larger.

geojson GeoJSON

SettingAcceptsDefaultWhat it does
geometry geometrycollection, linestring, mixed, multilinestring, multipoint, multipolygon, point, polygon mixed Which kind of geometry each feature carries. With mixed the seven kinds take turns, so a file of seven features or more holds every one of them.
formatting indented, minified, record-per-line record-per-line How the document is laid out. Every reader accepts all three - minified puts the whole file on one line and ends without a newline, and indented puts every number on its own line, which makes the same features several times larger.
precision 0 - 15 decimal places 6 How many decimal places every coordinate is written with. Six is about ten centimetres on the ground, the figure RFC 7946 gives.
altitude true or false false Whether every position carries a third number, the height in metres from -400 to 8848. A program that reads two numbers a position has to ignore it or refuse the file.
vertices 3 - 1000000 points 8 How many points every line, outline and MultiPoint has. A feature larger than 1 MiB is followed by spaces that fill the last bytes, and at precision 3 or less fewer points fit, because each needs its own step of longitude.
holes 0 - 100000 holes 0 How many holes every polygon has inside its outline. Each hole has four points and runs the other way round to its outline, as RFC 7946 asks. Holes need 6 or more vertices, fewer of them fit at precision 3 or less, and points and lines do not change.
winding reversed, rfc7946 rfc7946 Which way polygon outlines run - rfc7946 is counter-clockwise and reversed is clockwise, and holes always run the other way. RFC 7946 tells readers to accept both, and they disagree about which side of the outline is inside. Points and lines do not change.
antimeridian true or false false Whether every line and outline crosses the 180th meridian without being cut in two. RFC 7946 asks for such shapes to be cut, and readers differ - read as flat coordinates, a crossing outline crosses itself and runs the other way round. A single point cannot cross and is placed beside it.
unlocated all, none, some none How many features have no place - RFC 7946 writes their geometry as null. some takes the place of every fifth feature, from the fifth on, and all takes it from every one, so the settings that shape a geometry change nothing.
ids mixed, none, number, string number Which type every feature id has. RFC 7946 allows a number or a string, mixed gives odd features a number and even ones a string such as f2, and none leaves the id out. Readers that turn the id into a key may keep only one of the two types.
bbox true or false false Whether the collection and every feature with a place carry a bbox, the box their coordinates lie in. The collection's bbox follows its features, because its extent is known only after the last one, and a box across the antimeridian has a west edge greater than its east edge, as RFC 7946 asks.

html HyperText Markup Language

SettingAcceptsDefaultWhat it does
structure document, fragment document Whether the file is a whole page or only the blocks that would sit inside one. A fragment has no doctype, no html element and no body, which is what a content field or the body of an email really holds. It is far smaller, so the smallest fragment sits well below the smallest page.
nesting 0 - 100000 0 How many div elements the content sits inside, each one inside the last. 0 puts it straight in the body, and the label stays outside so the page still says what it is. Chromium keeps 511 levels and moves the deeper ones out, and the Nu HTML Checker calls a page that deep an error. lxml drops the content of a page nested about 250 deep and keeps only the label, and jsdom, parse5 and DOMPurify can run out of stack writing out a page from about 2 000 deep.
characters ascii, international ascii Whether the page carries text outside ASCII. international adds paragraphs in Polish, Russian, Japanese and Arabic, the Arabic right to left, with emoji, a letter written as two code points and named and numbered entities. A program without a Japanese or Arabic font shows boxes in their place.
elements basic, every basic Which elements the page uses. basic is headings, paragraphs, lists, tables and quotes. every adds a block that uses every element of the HTML standard at least once, all 22 kinds of input and small pictures and a sound inside the page, with no script and nothing fetched from a network. A fragment has no head, so it leaves out the eight elements that only a whole page holds.
links 0 - 1000000 0 How many links the page carries, in a list above the pictures and the blocks. They go through 18 kinds in turn and then repeat - a link to the list itself, relative, to the folder above, from the root, a query alone, absolute with a query and a fragment, http, without a scheme, percent encoded, an international domain, a port, mailto:, tel:, ftp:, a download, a new window, nofollow and data: - and the text of each says which it is. Every address is on a domain kept for examples. DOMPurify with its defaults takes out the data: address and the target that opens a new window, and it ran out of 8 GB of memory over a million links, which lxml read in 3 seconds. The catalogue of every element has six links of its own, which this does not count.
bom true or false false Whether the file opens with a byte order mark. A reader that has to guess the encoding needs one, and a reader that does not expect it shows it as stray characters at the start of the file.
formatting indented, lines, minified lines How the page is laid out. minified puts the whole file on one line and ends without a newline. indented puts two spaces in front of a line for every element it sits in, and leaves the text of pre as it is. All three show the same. A program reading line by line gets a minified page as one line - Go's bufio.Scanner refuses a line past 64 KB unless given a larger buffer - and text read by joining what the elements hold runs the last word of one block into the first word of the next. Indented with nesting puts more spaces in front of every line with each level, so nesting 1000 makes a page of at least 1.9 MB.
styles embedded, inline, none none Whether the page carries CSS, and where. embedded puts the rules in a style element, in the head of a page and at the very start of a fragment. inline puts the same rules in a style attribute on every heading, paragraph, list, table and quote the page is filled with, and the page looks the same. DOMPurify with its defaults drops the style element without listing it as removed and keeps the attributes. lxml's text_content and BeautifulSoup on html5lib count the rules as text of the page. The catalogue of every element takes the embedded rules and no attributes.
inline 0 - 10000 0 How many pictures the page shows, each one a real file of its format written into the page as a data: URL, so opening the page fetches nothing. They sit above the blocks, each in a paragraph of its own, and each says which it is in its alt text.
inline_format the id of a picture format, such as png or jpg png The format of the pictures. Any format whose files are pictures, such as png, jpg or gif. Chromium shows every one of them but tiff.
inline_size a size such as 2mb 8kb How big each picture is. Inside the page it is base64 on one line, about a third larger. lxml, and BeautifulSoup on top of it, leave out a picture past about 7.1 MB unless told to read huge trees. On Linux lxml took over 20 seconds over such a page, and with a 15 MB picture it lost the rest of the page as well.

log Server and application log

SettingAcceptsDefaultWhat it does
entry_format apache-combined, apache-common, json-lines, nginx, plain, syslog apache-combined Which kind of log to write. Web server shapes carry a request and a status, the others carry a level and a message.
timestamps advancing, fixed advancing Whether each entry happens later than the one before it. Fixed puts every entry at the same instant, which is what this format did before it could advance.

ip_version mixed, v4, v6 v4 Which kind of client address appears. Choose v6 to find out whether a reader handles it.
line_ending crlf, lf lf How each line ends. Choose crlf for a log written by a Windows service.

otlp OpenTelemetry Protocol JSON

SettingAcceptsDefaultWhat it does
signal logs, metrics, traces traces Which kind of telemetry the file holds. traces writes spans, logs writes log records and metrics writes the measurements of a service, collected every interval. A file holds one kind, as the OTLP file format asks.
formatting indented, minified, record-per-line record-per-line How the file is laid out. Record per line puts one batch on each line, which is what the OTLP file exporter writes and the file receiver of the OpenTelemetry Collector reads, and the file name ends in .jsonl. Minified and indented make the whole file one request, the body to post to an OTLP endpoint, and the file name ends in .json. Posted as a body, a file of several lines loses every line after the first in the Collector, and its file receiver reads nothing from an indented file.
bom true or false false Whether the file opens with a byte order mark. A reader that has to guess the encoding needs one, and a reader that does not expect it shows it as stray characters at the start of the file.
batch 1 - 1000 512 How many spans or log records each line holds. 512 is the batch an OpenTelemetry SDK sends by default. Only the formatting record per line has batches. Beside other formatting, or beside the signal metrics, where a line holds one collection, a batch is refused.
start a moment in UTC such as 2026-08-01T12:00:00Z 2026-08-01T12:00:00Z The moment the first span or log record is dated, and the moment a service writing metrics started. The later ones follow it at the rate or every interval. Change it when the system that receives the file refuses or hides data that is too old.
rate 1 - 1000000 entries per second 1 How many traces or log records begin each second. Metrics are collected every interval instead, and beside signal metrics a rate is refused.
depth 1 - 100 3 How many spans each trace has, each one the child of the one before it. 1 leaves every span without a parent. It shapes spans, and beside signal logs or metrics it is refused.
status_mix client-errors, realistic, server-errors, success realistic Which response codes the requests end with. A code of 500 or above marks its span as an error, as the HTTP conventions of OpenTelemetry ask, and every other code leaves the status unset. It shapes spans, and beside signal logs or metrics it is refused.
level_mix debug, errors, quiet, realistic realistic Which severities the log records carry. Realistic is mostly INFO with some of the others. It shapes log records, and beside signal traces or metrics it is refused.
trace_context true or false true Whether every log record names the trace and the span it was written in. The file holds no spans, so those ids match nothing in it. It shapes log records, and beside signal traces or metrics it is refused.
metric_kind exponential-histogram, gauge, histogram, mixed, sum, summary mixed Which metrics the file holds. gauge writes jvm.cpu.recent_utilization and shop.orders.pending, sum writes jvm.cpu.time, jvm.class.loaded and jvm.memory.used, histogram writes http.server.request.duration in the buckets the OpenTelemetry conventions name, exponential histogram writes jvm.gc.duration in buckets that double every eight, and summary writes http.server.requests as three percentiles, the way Micrometer writes a timer. mixed writes all of them. gauge and sum each hold whole numbers and fractions.
temporality cumulative, delta cumulative Whether a sum or a histogram counts everything since the service started or only what came since the collection before. cumulative is what an SDK sends by default. delta leaves jvm.memory.used cumulative, as the delta setting of an SDK does. Beside the metric kind gauge or summary it is refused.
exemplars true or false false Whether the durations of requests name the trace and the span a measurement was taken in, one for each bucket a collection measured in. The file holds no spans, so those ids match nothing in it. Only http.server.request.duration has them, and beside a metric kind without it they are refused.
interval 1 - 86400 seconds 60 How long a service waits between two collections of its metrics. 60 is what an SDK uses by default. Every point of a collection is dated at the same moment, and with the formatting record per line a line holds one collection.
id_encoding base64, hex, upper-hex hex How trace and span ids are written. hex is what the OTLP specification asks for. Upper-case hex writes the same digits in capitals, which the specification allows, and the OpenTelemetry Collector writes them back in lower case. base64 writes them the way the JSON mapping of protobuf writes bytes, which the specification forbids - the file receiver of the Collector drops every batch that holds an id without a word and its HTTP receiver answers 400. A reader built on the protobuf library reads base64 ids right and hex ids as something else.
enum_encoding name, number number How the kind of a span, the code of its status, the severity of a log record and the temporality of a sum or a histogram are written. number is what the OTLP specification asks for. name writes names such as SPAN_KIND_SERVER, which the specification forbids. The OpenTelemetry Collector reads them anyway and writes numbers back, and the Rust crate opentelemetry-proto refuses a span written that way.
key_case camel, snake camel How the keys of the file are written. camelCase is what the OTLP specification asks for, such as traceId. snake_case writes the names the .proto files give the fields, such as trace_id, which the specification calls not valid. The OpenTelemetry Collector reads them and writes camelCase back, and the Rust crate opentelemetry-proto refuses the file.
large_numbers number, text text How times and the other numbers of 64 bits are written. text is what the OTLP specification asks a writer for, such as "1785585600000000000". number writes them as JSON numbers, which a reader is told to take as well, and the OpenTelemetry Collector does. A reader that holds every JSON number as a double, as JavaScript does, gets every time to the nearest 256 nanoseconds.
time_order in-order, out-of-order in-order Whether every trace, log record or collection is dated later than the one before it. Out of order swaps the times of every two neighbours, so every second one is dated before the one in front of it. The specification of the OTLP file promises no order, and the OpenTelemetry Collector reads the file and writes it back unchanged. What the system storing the data does with what comes late is the question this file asks.
end_before_start true or false false Whether every span is dated with its end before its start, the two times changed places. The OpenTelemetry Collector reads such a span and writes it back unchanged. It shapes spans, and beside signal logs or metrics it is refused.
empty_envelope true or false false Whether the file opens with a line holding a batch with nothing in it, which the OTLP specification asks senders not to write. The file receiver of the OpenTelemetry Collector reads the line and writes nothing for it. Only the formatting record per line has a line to spare, and beside other formatting it is refused.
body any-value, text text What the body of a log record holds. Text is a sentence. Every kind of value gives the seven kinds of value OTLP has in turn - text, a boolean, the whole number 2^53 + 1, a fraction, a list, a map and bytes - and the OpenTelemetry Collector reads them and writes them back unchanged. With large numbers written as JSON numbers, a reader that holds numbers as doubles reads that whole number one less. It shapes log records, and beside signal traces or metrics it is refused.
non_finite true or false false Whether jvm.cpu.recent_utilization reports values that are not numbers: NaN in the second of every four collections, and Infinity and -Infinity in turn in the fourth, written as text the way the JSON mapping of protobuf writes them. The OpenTelemetry Collector reads them and writes them back unchanged. Beside a metric kind without that gauge it is refused.

pdf Portable Document Format

SettingAcceptsDefaultWhat it does
pages 1 - 5000 1 How many pages the document has.
page_size a3, a4, a5, legal, letter, mixed a4 The paper size every page uses. Mixed goes through a4, letter, legal, a3 and a5 in turn, one a page, and needs at least two pages.
orientation landscape, mixed, portrait portrait Whether pages stand upright or lie wide. Mixed alternates the two, starting upright, and needs at least two pages.
rotate 0, 90, 180, 270 0 Asks the reader to turn every page clockwise by this many degrees when it shows it. The page itself stays upright, so a reader that ignores the request shows it unturned.
pdf_version 1.4, 1.7 1.7 The version written at the start of the file. Nothing else changes, because the document uses nothing newer than 1.4.
title any text The title a reader shows in its title bar and in the document properties. Left empty, the title is the self describing label, or the name of this tool without one.
author any text The author in the document properties. Left empty, the document names none.
subject any text The subject in the document properties. Left empty, the document has none.
keywords any text The keywords in the document properties, as one line of text. Left empty, the document has none.
creator any text The program the document says it was written in, such as Microsoft Word. Left empty, the document names none.
producer any text Testing Files Generator The program the document says turned it into a PDF.
created a date such as 2024-02-29 or 2024-02-29T13:45:00+02:00, or none 2020-01-01T00:00:00Z When the document says it was created. A time written without a zone is kept without one, and none leaves the date out.
modified a date such as 2024-02-29 or 2024-02-29T13:45:00+02:00, or none When the document says it was last changed, written the same way as created. Left empty, the document has no such date.

rtf Rich Text Format

SettingAcceptsDefaultWhat it does
characters ascii, international ascii Whether the document carries text outside ASCII. international adds paragraphs in Polish, Russian, Japanese and Arabic, the Arabic right to left, and one with emoji, a letter written as two code points, the three characters RTF escapes and the ones it names, such as the dashes and the quotes. A program without a Japanese or Arabic font shows boxes in their place.
text_encoding both, codepage, literal, unicode unicode How the letters outside ASCII are written, which changes nothing while the characters are ascii. unicode writes each one as a number with a question mark after it for a reader that does not know numbers. Unicode and code page also puts the letter in the code page of its font after the number, two bytes for Japanese, the way Word writes it. Code page writes only the code page bytes, and the emoji still as numbers, since no code page holds them. literal writes the question mark as a plain character. LibreOffice, Tika and the RichEdit control of Windows read all four. pandoc shows code page text in the wrong letters. pandoc before 3.13 also drops the character after every letter written literal, and pandoc 3.1 and 3.7 drop the emoji in all four. striprtf returns an emoji as two halves, which Python refuses to write as UTF-8.
elements basic, every basic Which parts the document uses. basic is headings, paragraphs with bold and italic words, lists, tables and indented quotes. every adds document properties, a page header and footer, a footnote, a comment, hidden text, a link, a bookmark, a group every reader has to skip, a word no reader knows and line, tab, page and section breaks, and each part says where it is. Tika returns the most of them, the header, the footer and the comment among them. LibreOffice, striprtf and RichEdit return the hidden text as text, RichEdit with the address of the link, and pandoc returns the footnote and leaves the hidden text out.
nesting 0 - 10000000 0 How many groups the content sits inside, each one inside the last. 0 puts it straight in the document, and the label stays outside so the file still says what it is. No reader measured lost the content at 10 000 000 levels, but LibreOffice took 18.5 GB of memory over them and pandoc 14.5 GB, against about 2 GB each at 1 000 000.
links 0 - 1000000 0 How many links the document carries, each a HYPERLINK field in a paragraph of its own, above the pictures and the blocks. They go through 17 kinds in turn and then repeat - a link to a bookmark in the document, relative, to the folder above, from the root, absolute with a query and a fragment, absolute with a location, http, without a scheme, percent encoded, an international domain, a port, mailto:, tel:, ftp:, a new window, a screen tip and data: - and the text of each says which it is. Every address is on a domain kept for examples. LibreOffice turns the link without a scheme into a file:// address and rewrites the relative ones from where it saves the document. pandoc 3.12 leaves the bookmark link without an address, pandoc 3.1 and 3.7 drop every link with its text, and RichEdit returns the address of each link in front of its text. LibreOffice took over 11 minutes over a million links. The catalogue of every part has one link of its own, which this does not count.
inline 0 - 10000 0 How many pictures the document shows, each a real file of its format in a paragraph of its own that starts with its name, such as inline_0001.png. They sit above the blocks, at 96 pixels to the inch and never wider than 6 inches. LibreOffice, pandoc and Tika return each file as it was written. RichEdit shows the same picture and writes it out again smaller.
inline_format the id of a picture format, such as png or jpg png The format of the pictures, png or jpg - the two picture formats RTF has a name for. Any other format is refused.
inline_size a size such as 2mb 8kb How big each picture is. Written in hex it takes twice as many bytes in the document, with a line end every 128 characters. Written binary it takes its own size.
picture_data binary, hex hex How the bytes of each picture are written, which changes nothing while the document has no pictures. hex writes them as text, twice as large, the way LibreOffice writes them. binary writes them as they are, so the document is no longer text, and a program that counts braces or reads it as text loses its place. pandoc changes the line ends inside a binary picture, so no png comes out whole, and it can lose the text after the picture or refuse the whole document. LibreOffice, Tika and RichEdit read both.
