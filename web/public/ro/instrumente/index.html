Documentație

Verifică o arhivă înainte de dezarhivare și sumele de control

Pe lângă generator, tfg are mici instrumente pentru fișiere pe care le ai deja: dacă o arhivă poate fi dezarhivată în siguranță și dacă un fișier sau un folder întreg este încă ce spune suma lui de control. Rulează pe calculatorul tău, fără să încarci nimic și fără cont.

Răspunsul scurt

tfg tool archive-scan download.zip citește arhiva fără să dezarhiveze nimic și se termină cu codul 0 când este sigură sau cu 7 și o listă cu ce a găsit. tfg tool checksum setup.exe --expected <sum> spune dacă un fișier se potrivește cu suma dată de o pagină de descărcare.

Ce există

Ce instrumente există?

Aceasta este lista pe care o afișează programul, citită din el când se construiește pagina. tfg tool list o afișează pe aceeași, iar tfg tool show <id> spune ce primește fiecare dintre ele. Fiecare instrument este și pe ecranul Tools al ferestrei, cu aceleași setări.

Instrument La ce răspunde
archive-scan Poate fi dezarhivată în siguranță această arhivă?
checksum Este acest fișier cel care pretinde că este?
checksum-check Corespunde fiecare fișier în continuare cu fișierul lui de sume de control?
checksum-write Cum voi ști mai târziu că niciunul dintre aceste fișiere nu s-a schimbat?

Arhive

Poate fi dezarhivată în siguranță această arhivă? Zip slip și zip bombs

archive-scan se uită într-un fișier ZIP, TAR, TAR.GZ sau gzip fără să scrie nimic pe disc și spune dacă dezarhivarea lui este sigură. Raportează:

  • o intrare care ar fi scrisă în afara folderului, capcana cunoscută drept zip slip
  • o legătură, un dispozitiv sau două nume care ar ajunge în același fișier
  • un nume pe care un sistem nu îl poate scrie
  • o intrare construită ca să explodeze la dezarhivare, capcana cunoscută drept zip bomb
  • o intrare deteriorată

Arhivele din interiorul arhivei, de exemplu un ZIP într-un ZIP sau un DOCX într-un TAR, sunt citite la fel, în memorie, până la 16 niveluri în adâncime. O capcană în una dintre ele este o capcană în întreg, pentru că un program care dezarhivează totul le dezarhivează și pe ele. 

tfg tool archive-scan upload.zip
tfg tool archive-scan backup.tar.gz --unpacked_limit 500mb

--unpacked_limit raportează și o arhivă care, dezarhivată, ocupă mai mult decât permiți. Pentru o arhivă sigură comanda se termină cu codul 0, iar dacă găsește ceva, cu 7, așa că un pipeline se poate opri aici.

Un fișier

Este acest fișier cel care pretinde că este?

checksum calculează suma de control a unui fișier și, dacă îi dai una cu care să o compare, spune dacă se potrivesc. Acceptă md5, sha1, sha256, sha512 și crc32, sha256 dacă nu ceri altceva, și recunoaște după lungime ce fel de sumă i-ai dat. 

tfg tool checksum installer.msi
tfg tool checksum installer.msi --expected 9f86d081884c7d659a2feaa0c55ad015a3bf4f1b2b0b822cd15d6c15b0f00a08

O sumă care nu se potrivește se termină cu codul 7. Răspunde la aceeași întrebare ca Get-FileHash pe Windows sau sha256sum pe Linux, dar face comparația în locul tău.

Un folder întreg

S-a schimbat ceva în acest folder?

checksum-write scrie suma de control a fiecărui fișier dintr-un folder într-un SHA256SUMS de lângă ele, cu aceiași octeți pe care îi scrie sha256sum, și niciodată peste unul care există deja. checksum-check verifică apoi fiecare fișier pe care îl listează SHA256SUMS. 

tfg tool checksum-write ./fixtures
tfg tool checksum-check ./fixtures/SHA256SUMS

Fișierele pe care nu le listează nu sunt verificate, la fel ca la sha256sum -c, iar o cale care iese din folder este refuzată în loc să fie citită. Fișierele de exemplu vin cu un SHA256SUMS pe care îl poți verifica așa.
