Сценарії

Тест-кейси для завантаження файлів і файли для їх запуску

Чек-лист тест-кейсів для завантаження файлів, від ліміту розміру до імені файлу, яке намагається вийти зі своєї теки. Для кожного кейсу вказано файл, який його перевіряє, і те, що ваша система має з ним зробити, тож список можна запустити, а не лише прочитати.

Увесь список однією командою

tfg generate --preset upload-validation --limit 10mb --allow jpg,png,pdf --out ./upload записує файл майже для кожного кейсу нижче разом із маніфестом, у якому сказано, що має статися з кожним із них. Вкажіть ліміт і типи, які оголошує ваша форма.

accept означає, що ваша система має прийняти файл, а reject - що вона має відхилити його зі зрозумілим повідомленням. unspecified означає, що правильною може бути будь-яка відповідь, тож запишіть, яку з них обирає ваша система, і перевіряйте, що вона робить так щоразу. Слово після результату - це причина, яку вказує маніфест.

Розмір

Чи застосовується ліміт розміру там, де його оголошено?

Тест-кейсФайлОчікується
На байт менше за ліміт10mb_under_1b.jpgaccept
Рівно за лімітом10mb_at_limit.jpgaccept
На байт більше за ліміт10mb_over_1b.jpgreject size_limit
Удвічі більше за ліміт, щоб переконатися, що сервер припиняє читання рано, а не завантажує все в пам'ять10mb_far_over_2x.jpgreject size_limit
Порожній файл розміром 0 байтівempty.jpgunspecified size_zero

Найчастіше ліміт помиляється у двох випадках: коли його перевіряють лише в браузері і коли його рахують у МБ там, де код рахує МіБ. Пресет size-boundaries кладе файл на кожній відстані від обраного вами ліміту: байт, кілобайт і мегабайт в обидва боки.

Тип

Чи приймає форма потрібні типи й відхиляє решту?

Тест-кейсФайлОчікується
Кожен тип, який приймає форма, у вигляді справжнього файлу цього типуallowed_jpg.jpg, allowed_png.png, allowed_pdf.pdfaccept
Тип, який форма не приймаєdenied.svg, denied.html, denied.exe, denied.shreject extension_rule
Розширення каже про один тип, а вміст іншого, наприклад PDF з ім'ям .jpgpdf_as_jpg.jpg, png_as_pdf.pdf, jpg_as_png.pngreject mime_mismatch
Два розширення, останнє не дозволенеinvoice.jpg.exereject extension_rule
Розширення немає зовсімinvoiceunspecified extension_rule
Розширення великими літерамиPHOTO.JPGunspecified extension_rule

Файл SVG або HTML, прийнятий за зображення чи простий текст, дає змогу провести скрипт крізь форму. Тому вони в списку типів, які треба відхиляти, якщо ваша форма не має їх приймати.

Вміст

Чи відкриває система файл, чи дивиться лише на ім'я?

Тест-кейсФайлОчікується
Файл, обрізаний так, як його залишає перерване завантаженняcorrupt-truncate.pdfreject content_malformed
Файл, перші байти якого - нулі, тож ніщо не каже, що це за файлcorrupt-zero-head.pngreject content_malformed
Найменший файл, який допускає формат, коректний і крихітнийtfg generate --preset empty-and-minimalaccept

Файл, у якого правильні лише ім'я і розмір, проходить будь-яку перевірку, яка його не відкриває. Пошкоджені приклади файлів є у форматах PDF, Word, Excel, PowerPoint, JPG, PNG, MP4 і ZIP, а на сторінці Пошкоджені тестові файли описано, як зробити їх у будь-якому форматі й будь-якого розміру.

Ім'я

Чи повертається файл під тим ім'ям, яке йому дали?

Тест-кейсФайлОчікується
Пробіли й дужкиmy report (final) v2.jpgaccept
Літери поза ASCII та емодзіwiadomość_日本語_🎉.jpgunspecified filename_invalid
Ім'я, довше за 200 символівaaa...aaa.jpgunspecified filename_too_long
Ім'я, яке вибирається зі своєї теки, ../ або ..\climbing_name.jpg, завантажується як ../tfg_climbed_out.jpgunspecified filename_traversal
Абсолютний шлях, у Linux або Windowsabsolute_name.jpg, завантажується як /tmp/tfg_climbed_out.jpgunspecified filename_traversal

Ім'я зі шляхом не можна зберегти на диск, тому файл має звичайне ім'я, а маніфест каже, під яким ім'ям його завантажити. Прийняти файл і залишити лише останню частину імені - гарна відповідь. Записати його поза текою завантаження - той дефект, заради якого цей кейс і існує. Пресет filename-handling містить набагато більше імен: схожі одна на одну літери, невидимі символи, імена, зарезервовані Windows, і довжини, які рахуються в байтах.

Обсяг і архіви

Що відбувається з багатьма файлами або з файлом, у якому їх багато?

Тест-кейсФайлОчікується
П'ятдесят файлів в одному завантаженнівід bulk_0001.jpg до bulk_0050.jpgaccept
ZIP, у якому справді 200 документівtfg generate --format zip --size 5mb --set entries=200 --set entry_format=pdfaccept
Архів, який розпаковує ваша система, спершу перевірений на zip slip і zip-бомбиtfg tool archive-scan upload.zipбезпечний або що знайдено

--bulk задає, скільки файлів входить у масове завантаження, до десяти тисяч. На сторінці Інструменти описано, що шукає перевірка архіву.

У тесті

Запуск списку як тесту

Маніфест містить очікуваний результат для кожного файлу та ім'я, під яким його завантажувати, тому один цикл проходить увесь список: 

import json, os

directory = "upload"
manifest = json.load(open(os.path.join(directory, "manifest.json")))

for entry in manifest["files"]:
    outcome = entry["expected"]["outcome"]
    if outcome == "unspecified":
        continue
    name = entry.get("send_as", entry["name"])
    response = upload(os.path.join(directory, entry["path"]), name)
    assert response.ok == (outcome == "accept"), name

Файли з позначкою unspecified тут пропускаються, бо відповідь для них - ваша власна політика. Ухваліть рішення, запишіть його в рецепт через expected, і цикл перевірить і їх. Тестові файли в CI показують, як запустити це в конвеєрі.
