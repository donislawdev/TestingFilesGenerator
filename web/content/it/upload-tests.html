Casi di test per l'upload di file, con i file per eseguirli

Una checklist di casi di test per l'upload di file, dal limite di dimensione a un nome di file che cerca di uscire dalla sua cartella. Ogni caso indica il file che lo verifica e cosa il tuo sistema deve farne, così la lista si può eseguire e non solo leggere.

Tutta la lista con un comando

tfg generate --preset upload-validation --limit 10mb --allow jpg,png,pdf --out ./upload scrive un file per quasi ogni caso qui sotto, con un manifest che dice cosa deve succedere a ciascuno. Inserisci il limite e i tipi che il tuo modulo dichiara.

accept significa che il tuo sistema deve accettare il file e reject che deve rifiutarlo con un messaggio chiaro. unspecified significa che entrambe le risposte possono essere giuste, quindi annota quale intende il tuo sistema e controlla che si comporti così ogni volta. La parola dopo l'esito è il motivo indicato dal manifest.

Un file che ha solo il nome giusto e la dimensione giusta supera ogni controllo che non lo apre mai. I file di esempio corrotti ci sono in PDF, Word, Excel, PowerPoint, JPG, PNG, MP4 e ZIP, e file di test corrotti spiega come crearli in qualsiasi formato e di qualsiasi dimensione.

Un percorso dentro un nome non si può salvare su disco, quindi il file ha un nome semplice e il manifest dice con quale nome caricarlo. Accettare il file e tenere solo l'ultima parte del nome è una buona risposta. Scriverlo fuori dalla cartella di upload è il difetto che questo caso esiste per trovare. Il preset filename-handling ha molti altri nomi: lettere che si somigliano, caratteri invisibili, nomi riservati da Windows e lunghezze contate in byte.

In un test

Eseguire la lista come test

Il manifest contiene l'esito atteso di ogni file e il nome con cui caricarlo, quindi un solo ciclo esegue tutta la lista: 

import json, os

directory = "upload"
manifest = json.load(open(os.path.join(directory, "manifest.json")))

for entry in manifest["files"]:
    outcome = entry["expected"]["outcome"]
    if outcome == "unspecified":
        continue
    name = entry.get("send_as", entry["name"])
    response = upload(os.path.join(directory, entry["path"]), name)
    assert response.ok == (outcome == "accept"), name

I file marcati unspecified sono esclusi qui, perché la loro risposta è la tua politica. Decidila, scrivila nella ricetta con expected, e il ciclo controlla anche quelli. File di test in CI esegue tutto questo in una pipeline.
