ファイルアップロードのテストケースと、実行するためのファイル

ファイルアップロードのテストケースのチェックリストです。サイズ制限から、自分のフォルダーの外に出ようとするファイル名まであります。どのケースにも、それをテストするファイルと、システムがそのファイルをどう扱うべきかが書かれているので、読むだけでなく実行できるリストです。

リスト全体をコマンド1つで

tfg generate --preset upload-validation --limit 10mb --allow jpg,png,pdf --out ./uploadは、以下のほぼすべてのケースのファイルを、各ファイルがどうなるべきかを示すマニフェストと一緒に書き出します。制限値と種類には、フォームが宣言しているものを入れてください。

acceptは、システムがファイルを受け入れるべきことを、rejectは、わかりやすいメッセージとともに拒否するべきことを意味します。unspecifiedは、どちらの答えも正しくありうるという意味です。システムがどちらを意図しているかを書き留め、毎回そのとおりに動くかを確認してください。結果の後ろの語は、マニフェストが示す理由です。

サイズ

サイズ制限は、宣言した位置で適用されていますか。

テストケースファイル期待される結果
制限より1バイト小さい10mb_under_1b.jpgaccept
ちょうど制限値10mb_at_limit.jpgaccept
制限より1バイト大きい10mb_over_1b.jpgreject size_limit

制限で最も多い間違いは2つです。ブラウザーだけで確認している制限と、MBで宣言した制限をコードがMiBで数えているケースです。size-boundariesプリセットは、選んだ制限からのあらゆる距離、つまり両側に1バイト、1キロバイト、1メガバイトの位置にファイルを置きます。

種類

フォームは受け入れるべき種類を受け入れ、それ以外を拒否しますか。

画像やプレーンテキストとして受け入れられたSVGやHTMLファイルは、スクリプトにフォームをすり抜けさせる手口になります。そのため、フォームが意図して受け入れるのでない限り、拒否すべき種類のリストに入っています。

中身

システムはファイルを開いていますか。それとも名前だけを見ていますか。

テストケースファイル期待される結果
途中で止まったアップロードが残すような、途中で切れたファイルcorrupt-truncate.pdfreject content_malformed
先頭のバイトがゼロで、何のファイルかを示すものがないファイルcorrupt-zero-head.pngreject content_malformed
形式が許す最小のファイル。有効で、ごく小さいものtfg generate --preset empty-and-minimalaccept

名前とサイズだけが正しいファイルは、ファイルを開かない検査をすべて通過します。破損したサンプルファイルはPDF、Word、Excel、PowerPoint、JPG、PNG、MP4、ZIPで用意しています。破損したテストファイルでは、任意の形式と任意のサイズで作る方法を説明しています。

名前

ファイルは、付けられた名前のまま戻ってきますか。

テストケースファイル期待される結果
スペースとかっこmy report (final) v2.jpgaccept
ASCII以外の文字と絵文字wiadomość_日本語_🎉.jpgunspecified filename_invalid
200文字を超える名前aaa...aaa.jpgunspecified filename_too_long
../や..\でフォルダーの外へ出る名前climbing_name.jpg、../tfg_climbed_out.jpgとしてアップロードunspecified filename_traversal
LinuxまたはWindowsの絶対パスabsolute_name.jpg、/tmp/tfg_climbed_out.jpgとしてアップロードunspecified filename_traversal

パスを含む名前はディスクに保存できないため、ファイルには普通の名前が付いていて、どの名前でアップロードするかはマニフェストに書かれています。ファイルを受け入れて名前の最後の部分だけを残すのは、よい答えです。アップロードフォルダーの外に書き込むことこそ、このケースが見つけるための欠陥です。filename-handlingプリセットには、さらに多くの名前があります。よく似た文字、不可視文字、Windowsが予約している名前、バイトで数える長さなどです。

テストで

リストをテストとして実行する

マニフェストには、各ファイルの期待される結果と、アップロードするときの名前が入っているので、1つのループでリスト全体を実行できます。 

import json, os

directory = "upload"
manifest = json.load(open(os.path.join(directory, "manifest.json")))

for entry in manifest["files"]:
    outcome = entry["expected"]["outcome"]
    if outcome == "unspecified":
        continue
    name = entry.get("send_as", entry["name"])
    response = upload(os.path.join(directory, entry["path"]), name)
    assert response.ok == (outcome == "accept"), name

unspecifiedのファイルはここでは除外しています。その答えはあなた自身の方針で決まるからです。方針を決めてレシピにexpectedとして書けば、ループはそれらも確認します。CIでのテストファイルでは、これをパイプラインで実行します。
