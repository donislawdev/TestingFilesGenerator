File upload test cases, with the files to run them

A checklist of test cases for a file upload, from the size limit to a file name that tries to leave its folder. Every case names the file that tests it and what your system should do with it, so the list can be run and not only read.

The whole list in one command

tfg generate --preset upload-validation --limit 10mb --allow jpg,png,pdf --out ./upload writes a file for nearly every case below, with a manifest that says what should happen to each. Put in the limit and the types your form declares.

accept means your system should take the file and reject that it should turn it away with a clear message. unspecified means either answer can be right, so write down which one your system means, and check that it does that every time. The word after the outcome is the reason the manifest gives.

The two cases a limit most often gets wrong are a limit checked only in the browser, and a limit counted in MB where the code counts MiB. The size-boundaries preset puts a file at every distance from the limit you choose, a byte, a kilobyte and a megabyte either side.

An SVG or an HTML file taken for a picture or for plain text is a way to get a script past a form, which is why they are on the list of types to refuse unless your form means to take them.

Content

A file cut short, the way an interrupted upload leaves itcorrupt-truncate.pdfreject content_malformed

A file that only has the right name and the right size passes every check that never opens it. Corrupt sample files come in PDF, Word, Excel, PowerPoint, JPG, PNG, MP4 and ZIP, and corrupt test files says how to make them in any format at any size.

A path in a name cannot be saved to a disk, so the file keeps a plain name and the manifest says which name to upload it under. Taking the file and keeping only the last part of the name is a good answer. Writing it outside the upload folder is the defect this case exists to find. The filename-handling preset has many more names: look-alike letters, invisible characters, names reserved by Windows and lengths counted in bytes.

In a test

Running the list as a test

The manifest holds the expected outcome of every file and the name to upload it under, so one loop runs the whole list: 

import json, os

directory = "upload"
manifest = json.load(open(os.path.join(directory, "manifest.json")))

for entry in manifest["files"]:
    outcome = entry["expected"]["outcome"]
    if outcome == "unspecified":
        continue
    name = entry.get("send_as", entry["name"])
    response = upload(os.path.join(directory, entry["path"]), name)
    assert response.ok == (outcome == "accept"), name

The files marked unspecified are left out here, because their answer is your own policy. Decide it, write it into the recipe with expected, and the loop checks them too. Test files in CI runs this in a pipeline.
