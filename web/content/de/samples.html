Beispieldateien zum Testen

Echte Dateien zum Herunterladen, um ein Upload-Formular, einen Parser oder einen Import zu testen: eine Datei von jedem Format, das dieser Generator schreibt, absichtlich beschädigte Dateien, Tabellen so, wie Tabellenkalkulationen sie exportieren, und Platzhalterbilder. Nichts zu installieren und keine Anmeldung.

Aus einem einzigen Rezept

Alle Dateien auf dieser Seite stammen aus einem Rezept, samples.yaml. Führst du es mit tfg aus, bekommst du auf jedem Rechner dieselben Bytes. Die SHA-256-Summe neben jeder Datei kannst du also selbst nachprüfen, statt sie einfach zu glauben. 

tfg generate samples.yaml --out samples

Alle Summen stehen in SHA256SUMS. Leg die Datei in diesen Ordner, dann sagt dir tfg tool checksum-check samples/SHA256SUMS oder sha256sum -c SHA256SUMS, ob jede Datei passt.

Die letzte Spalte jeder Tabelle zeigt, was das Manifest von deinem System mit der Datei erwartet. accept heißt, dass es die Datei annehmen soll, reject, dass es sie abweisen soll, und unspecified, dass es von den Regeln deines Systems abhängt.

Jedes Format

Eine Datei von jedem Format, jede 1 MB groß

Dokumente, Bilder, Text, Daten, Archive, E-Mail, Telemetrie, Audio und Video, jede Datei genau 1 048 576 Bytes groß und jede eine echte Datei ihres Formats. Das PDF öffnet sich in einem PDF-Reader, die DOCX in Word, die XLSX in Excel, und das ZIP lässt sich entpacken.

Eine andere Größe ist ein einziger Befehl. tfg generate --format pdf --size 10mb schreibt ein PDF von genau 10 MB, und eine Datei mit 1 GB entsteht auf dieselbe Weise. So große Dateien liegen nicht auf dieser Seite, weil ein Befehl sie schneller erzeugt, als ein Download dauern würde.

Absichtlich kaputt

Beschädigte Dateien: PDF, Word, Excel, Bilder, Video und ZIP

Jede Datei wurde zuerst gesund erzeugt und dann beschädigt, und jede ist trotzdem genau 1 MB groß. truncate schneidet das Ende ab, so wie es ein abgebrochener Upload tut, und zero-head schreibt Nullen über die ersten Bytes, an denen ein Leser erkennt, was die Datei ist. Das Manifest erwartet, dass dein System jede von ihnen abweist.

Für einen Import

CSV-, JSON- und Excel-Tabellen

Dieselbe Tabelle so geschrieben, wie echte Programme sie schreiben: mit Komma, Semikolon, Tabulator oder senkrechtem Strich zwischen den Werten, mit Windows-Zeilenenden, ohne Kopfzeile, mit jedem Wert in Anführungszeichen oder mit keinem, eine breite CSV, ein Excel-Blatt und JSON in drei Layouts. Manche sind mit unspecified markiert, weil dein Import selbst entscheidet, ob er ein Semikolon annimmt. Was er nicht tun darf, ist, nur die Hälfte der Tabelle einzulesen.

Für ein Layout

Platzhalterbilder in gängigen Größen

Ein einfarbig graues Bild mit seiner Größe in der Mitte, um eine Seite zu gestalten, bevor es die echten Bilder gibt: quadratische Vorschaubilder, eine Anzeige mit 300 x 250, ein Banner mit 728 x 90, eine Social-Media-Karte mit 1200 x 630 und ein Full-HD-Bildschirm. Jede Datei ist so klein, wie das Bild sein kann.

Jede andere Größe oder Farbe:

tfg generate --format png --size smallest --set content=placeholder --set width=640 --set height=360 --set background=1e293b

Das Preset picture-sizes erzeugt in einem Lauf jede Größe, die Bildschirme und Plattformen verwenden, mit --content placeholder.
