Testfälle für den Datei-Upload, mit den Dateien dazu

Eine Checkliste mit Testfällen für einen Datei-Upload, vom Größenlimit bis zu einem Dateinamen, der aus seinem Ordner auszubrechen versucht. Jeder Fall nennt die Datei, die ihn prüft, und was dein System mit ihr tun soll. So lässt sich die Liste ausführen und nicht nur lesen.

Die ganze Liste mit einem Befehl

tfg generate --preset upload-validation --limit 10mb --allow jpg,png,pdf --out ./upload schreibt eine Datei für fast jeden Fall unten, mit einem Manifest, das sagt, was mit jeder geschehen soll. Setze das Limit und die Typen ein, die dein Formular angibt.

accept heißt, dass dein System die Datei annehmen soll, und reject, dass es sie mit einer klaren Meldung abweisen soll. unspecified heißt, dass beide Antworten richtig sein können. Halte also fest, welche dein System meint, und prüfe, dass es das jedes Mal tut. Das Wort nach dem Ergebnis ist der Grund, den das Manifest angibt.

Am häufigsten geht ein Limit auf zwei Arten schief: Es wird nur im Browser geprüft, oder es wird in MB gezählt, wo der Code MiB zählt. Das Preset size-boundaries legt Dateien in jeden Abstand um das Limit, das du wählst, ein Byte, ein Kilobyte und ein Megabyte auf beiden Seiten.

Eine SVG- oder HTML-Datei, die als Bild oder als einfacher Text angenommen wird, ist ein Weg, ein Skript an einem Formular vorbeizuschleusen. Deshalb stehen sie auf der Liste der Typen, die abgewiesen werden sollen, außer dein Formular soll sie annehmen.

Eine Datei, die nur den richtigen Namen und die richtige Größe hat, besteht jede Prüfung, die sie nie öffnet. Beschädigte Beispieldateien gibt es als PDF, Word, Excel, PowerPoint, JPG, PNG, MP4 und ZIP, und Beschädigte Testdateien erklärt, wie du sie in jedem Format und in jeder Größe erzeugst.

Einen Namen mit Pfad kann man nicht auf einer Festplatte speichern. Die Datei trägt deshalb einen einfachen Namen, und das Manifest sagt, unter welchem Namen sie hochgeladen werden soll. Die Datei anzunehmen und nur den letzten Teil des Namens zu behalten, ist eine gute Antwort. Sie außerhalb des Upload-Ordners zu schreiben, ist der Fehler, für den es diesen Fall gibt. Das Preset filename-handling hat viele weitere Namen: verwechselbar ähnliche Buchstaben, unsichtbare Zeichen, von Windows reservierte Namen und Längen, die in Bytes gezählt werden.

--bulk legt fest, wie viele Dateien der Massen-Upload enthält, bis zu zehntausend. Die Seite Werkzeuge erklärt, wonach die Archivprüfung sucht.

In einem Test

Die Liste als Test ausführen

Das Manifest enthält das erwartete Ergebnis jeder Datei und den Namen, unter dem sie hochgeladen werden soll. Eine einzige Schleife führt also die ganze Liste aus: 

import json, os

directory = "upload"
manifest = json.load(open(os.path.join(directory, "manifest.json")))

for entry in manifest["files"]:
    outcome = entry["expected"]["outcome"]
    if outcome == "unspecified":
        continue
    name = entry.get("send_as", entry["name"])
    response = upload(os.path.join(directory, entry["path"]), name)
    assert response.ok == (outcome == "accept"), name

Die mit unspecified markierten Dateien werden hier ausgelassen, weil ihre Antwort deine eigene Richtlinie ist. Entscheide sie, schreib sie mit expected ins Rezept, dann prüft die Schleife auch diese Dateien. Testdateien in CI führt das in einer Pipeline aus.
