文件上传测试用例，附带运行它们的文件

一份文件上传测试用例的检查表，从大小限制到试图离开所在文件夹的文件名。每个用例都写明测试它的文件，以及你的系统应如何处理该文件，所以这份列表不只能读，还能直接运行。

一条命令生成整个列表

tfg generate --preset upload-validation --limit 10mb --allow jpg,png,pdf --out ./upload 会为下面几乎每个用例写出一个文件，并附带一份清单，说明每个文件应该得到什么结果。把限制和类型换成你的表单声明的值。

accept 表示你的系统应该接受该文件，reject 表示应该拒绝它并给出清楚的消息。unspecified 表示两种答案都可能正确，所以请写下你的系统采用哪一种，并检查它每次都这样做。结果后面的词是清单给出的原因。

大小

大小限制是否在声明的位置生效？

测试用例文件预期
比限制小一个字节10mb_under_1b.jpgaccept
恰好等于限制10mb_at_limit.jpgaccept
比限制大一个字节10mb_over_1b.jpgreject size_limit
限制的两倍，用来确认服务器会提前停止读取，而不是全部读进内存10mb_far_over_2x.jpgreject size_limit
0 字节的空文件empty.jpgunspecified size_zero

限制最常出错的两种情况是：只在浏览器中检查的限制，以及按 MB 声明、代码却按 MiB 计算的限制。size-boundaries 预设会在你选定的限制周围的每个距离上各放一个文件，即两侧各相差一个字节、一个千字节和一个兆字节。

类型

表单是否接受该接受的类型，并拒绝其余类型？

测试用例文件预期
表单接受的每种类型，各用一个该类型的真实文件allowed_jpg.jpg、allowed_png.png、allowed_pdf.pdfaccept
表单不接受的类型denied.svg、denied.html、denied.exe、denied.shreject extension_rule
扩展名是一种类型，内容却是另一种，例如命名为 .jpg 的 PDFpdf_as_jpg.jpg、png_as_pdf.pdf、jpg_as_png.pngreject mime_mismatch
两个扩展名，最后一个不被允许invoice.jpg.exereject extension_rule
完全没有扩展名invoiceunspecified extension_rule
大写的扩展名PHOTO.JPGunspecified extension_rule

被当作图片或纯文本接受的 SVG 或 HTML 文件，是让脚本绕过表单的一种办法。所以除非你的表单本来就要接受它们，否则它们都在应拒绝的类型列表中。

内容

系统是打开文件，还是只看文件名？

测试用例文件预期
被截短的文件，就像中断的上传留下的那样corrupt-truncate.pdfreject content_malformed
开头字节是零的文件，因此没有任何信息说明它是什么corrupt-zero-head.pngreject content_malformed
格式允许的最小文件，合法且极小tfg generate --preset empty-and-minimalaccept

一个只有名字和大小正确的文件，能通过所有不打开它的检查。损坏的示例文件有 PDF、Word、Excel、PowerPoint、JPG、PNG、MP4 和 ZIP 格式，损坏的测试文件介绍如何以任意格式、任意大小制作它们。

文件名

文件取回时还是原来的名字吗？

测试用例文件预期
空格和括号my report (final) v2.jpgaccept
非 ASCII 字母和 emojiwiadomość_日本語_🎉.jpgunspecified filename_invalid
超过 200 个字符的文件名aaa...aaa.jpgunspecified filename_too_long
用 ../ 或 ..\ 跳出所在文件夹的文件名climbing_name.jpg，以 ../tfg_climbed_out.jpg 的名字上传unspecified filename_traversal
Linux 或 Windows 上的绝对路径absolute_name.jpg，以 /tmp/tfg_climbed_out.jpg 的名字上传unspecified filename_traversal

带路径的名字无法保存到磁盘上，所以文件本身用普通的名字，清单会说明上传时用什么名字。接受文件并只保留名字的最后一部分，是好的处理方式。把它写到上传文件夹之外，正是这个用例要找出的缺陷。filename-handling 预设还有更多文件名：形似的字母、不可见字符、Windows 保留的名字，以及按字节计算的长度。

--bulk 设置批量上传包含多少个文件，最多一万个。工具说明压缩包检查会查找什么。

在测试中

把列表作为测试运行

清单包含每个文件的预期结果和上传时使用的名字，所以一个循环就能跑完整个列表： 

import json, os

directory = "upload"
manifest = json.load(open(os.path.join(directory, "manifest.json")))

for entry in manifest["files"]:
    outcome = entry["expected"]["outcome"]
    if outcome == "unspecified":
        continue
    name = entry.get("send_as", entry["name"])
    response = upload(os.path.join(directory, entry["path"]), name)
    assert response.ok == (outcome == "accept"), name

标为 unspecified 的文件在这里被跳过，因为它们的答案取决于你自己的策略。确定策略，用 expected 写进配方，循环就会一并检查它们。CI 中的测试文件会在流水线中运行这段代码。
