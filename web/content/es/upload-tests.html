Casos de prueba de subida de archivos, con los archivos para ejecutarlos

Una lista de comprobación de casos de prueba para la subida de archivos, desde el límite de tamaño hasta un nombre de archivo que intenta salir de su carpeta. Cada caso indica el archivo que lo prueba y lo que tu sistema debe hacer con él, así que la lista se puede ejecutar y no solo leer.

Toda la lista con un solo comando

tfg generate --preset upload-validation --limit 10mb --allow jpg,png,pdf --out ./upload escribe un archivo para casi todos los casos de abajo, con un manifiesto que dice qué debe pasar con cada uno. Pon el límite y los tipos que declara tu formulario.

accept significa que tu sistema debe aceptar el archivo y reject que debe rechazarlo con un mensaje claro. unspecified significa que cualquiera de las dos respuestas puede ser correcta, así que anota cuál elige tu sistema y comprueba que lo hace siempre. La palabra que sigue al resultado es el motivo que da el manifiesto.

¿Se aplica el límite de tamaño donde se declara?

Caso de pruebaArchivoEsperado
Un byte por debajo del límite10mb_under_1b.jpgaccept
Justo en el límite10mb_at_limit.jpgaccept
Un byte por encima del límite10mb_over_1b.jpgreject size_limit

Los dos fallos más habituales de un límite son un límite comprobado solo en el navegador y un límite contado en MB donde el código cuenta MiB. El preset size-boundaries pone un archivo a cada distancia del límite que elijas, un byte, un kilobyte y un megabyte a cada lado.

Un SVG o un HTML tomado por una imagen o por texto plano es una forma de colar un script por un formulario, y por eso están en la lista de tipos que rechazar, salvo que tu formulario quiera aceptarlos.

Contenido

¿Abre el sistema el archivo o solo mira su nombre?

Caso de pruebaArchivoEsperado
Un archivo cortado, como lo deja una subida interrumpidacorrupt-truncate.pdfreject content_malformed
Un archivo cuyos primeros bytes son ceros, así que nada dice qué escorrupt-zero-head.pngreject content_malformed

Un archivo que solo tiene el nombre correcto y el tamaño correcto pasa cualquier comprobación que no lo abre. Los archivos de ejemplo corruptos están en PDF, Word, Excel, PowerPoint, JPG, PNG, MP4 y ZIP, y archivos de prueba corruptos explica cómo crearlos en cualquier formato y de cualquier tamaño.

Nombre

¿Vuelve el archivo con el nombre que se le dio?

Caso de pruebaArchivoEsperado
Espacios y paréntesismy report (final) v2.jpgaccept
Letras fuera de ASCII y un emojiwiadomość_日本語_🎉.jpgunspecified filename_invalid
Un nombre de más de 200 caracteresaaa...aaa.jpgunspecified filename_too_long
Un nombre que sale de su carpeta, ../ o ..\climbing_name.jpg, subido como ../tfg_climbed_out.jpgunspecified filename_traversal
Una ruta absoluta, de Linux o de Windowsabsolute_name.jpg, subido como /tmp/tfg_climbed_out.jpgunspecified filename_traversal

Un nombre con una ruta no se puede guardar en un disco, así que el archivo lleva un nombre simple y el manifiesto dice con qué nombre subirlo. Aceptar el archivo y quedarse solo con la última parte del nombre es una buena respuesta. Escribirlo fuera de la carpeta de subida es el defecto que este caso existe para encontrar. El preset filename-handling tiene muchos más nombres: letras que se confunden con otras, caracteres invisibles, nombres reservados por Windows y longitudes contadas en bytes.

Volumen y archivos comprimidos

¿Qué pasa con muchos archivos, o con un archivo que contiene muchos?

Caso de pruebaArchivoEsperado
Cincuenta archivos en una sola subidade bulk_0001.jpg a bulk_0050.jpgaccept
Un ZIP que de verdad contiene 200 documentostfg generate --format zip --size 5mb --set entries=200 --set entry_format=pdfaccept

--bulk fija cuántos archivos contiene la subida masiva, hasta diez mil. Herramientas explica qué busca la comprobación de archivos comprimidos.

En una prueba

Ejecutar la lista como una prueba

El manifiesto guarda el resultado esperado de cada archivo y el nombre con el que subirlo, así que un solo bucle recorre toda la lista: 

import json, os

directory = "upload"
manifest = json.load(open(os.path.join(directory, "manifest.json")))

for entry in manifest["files"]:
    outcome = entry["expected"]["outcome"]
    if outcome == "unspecified":
        continue
    name = entry.get("send_as", entry["name"])
    response = upload(os.path.join(directory, entry["path"]), name)
    assert response.ok == (outcome == "accept"), name

Los archivos marcados como unspecified se omiten aquí, porque su respuesta es tu propia política. Decídela, escríbela en la receta con expected y el bucle también los comprueba. Archivos de prueba en CI ejecuta esto en un pipeline.
