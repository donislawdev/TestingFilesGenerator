Vérifier une archive avant de la décompresser, et contrôler les sommes

À côté du générateur, tfg a de petits outils pour les fichiers que vous avez déjà : savoir si une archive se décompresse sans danger, et si un fichier ou un dossier entier est toujours ce que dit sa somme de contrôle. Ils fonctionnent sur votre machine, sans envoi et sans compte.

La réponse courte

tfg tool archive-scan download.zip lit l'archive sans rien décompresser et se termine avec le code 0 si elle est sûre, ou 7 avec la liste de ce qu'il a trouvé. tfg tool checksum setup.exe --expected <sum> dit si un fichier correspond à la somme qu'une page de téléchargement vous a donnée.

Archives

Cette archive se décompresse-t-elle sans danger ? Zip slip et bombes zip

archive-scan regarde dans un fichier ZIP, TAR, TAR.GZ ou gzip sans rien écrire sur le disque et dit si sa décompression est sûre. Il signale :

  • une entrée qui serait écrite hors du dossier, le piège connu sous le nom de zip slip
  • un lien, un périphérique, ou deux noms qui aboutiraient au même fichier
  • un nom qu'un système ne peut pas écrire
  • une entrée conçue pour exploser à la décompression, le piège connu sous le nom de bombe zip
  • une entrée endommagée

Les archives contenues dans l'archive, comme un ZIP dans un ZIP ou un DOCX dans un TAR, sont lues de la même façon, en mémoire, jusqu'à 16 niveaux de profondeur. Un piège dans l'une d'elles est un piège dans l'ensemble, car un programme qui décompresse tout les décompresse aussi. 

tfg tool archive-scan upload.zip
tfg tool archive-scan backup.tar.gz --unpacked_limit 500mb

--unpacked_limit signale aussi une archive qui, décompressée, occupe plus que vous ne le permettez. Une archive sûre se termine avec le code 0 et toute trouvaille avec 7, si bien qu'un pipeline peut s'arrêter dessus.

Un fichier

Ce fichier est-il bien celui qu'il prétend être ?

checksum calcule la somme de contrôle d'un fichier et, si vous lui en donnez une à comparer, dit si elles correspondent. Il prend en charge md5, sha1, sha256, sha512 et crc32, sha256 sauf demande contraire, et reconnaît à sa longueur le type de somme que vous lui avez donné. 

tfg tool checksum installer.msi
tfg tool checksum installer.msi --expected 9f86d081884c7d659a2feaa0c55ad015a3bf4f1b2b0b822cd15d6c15b0f00a08

Une somme qui ne correspond pas se termine avec le code 7. Il répond à la même question que Get-FileHash sous Windows ou sha256sum sous Linux, avec la comparaison faite pour vous.

Un dossier entier

Quelque chose a-t-il changé dans ce dossier ?

checksum-write écrit la somme de contrôle de chaque fichier d'un dossier dans un SHA256SUMS placé à côté d'eux, avec les mêmes octets que ceux qu'écrit sha256sum, et jamais par-dessus un fichier déjà présent. checksum-check vérifie ensuite chaque fichier que liste SHA256SUMS. 

tfg tool checksum-write ./fixtures
tfg tool checksum-check ./fixtures/SHA256SUMS

Les fichiers qu'il ne liste pas ne sont pas examinés, comme avec sha256sum -c, et un chemin qui sort du dossier est refusé au lieu d'être lu. Les fichiers d'exemple sont fournis avec un SHA256SUMS que vous pouvez vérifier de cette façon.
