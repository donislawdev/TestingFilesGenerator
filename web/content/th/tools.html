ตรวจไฟล์บีบอัดก่อนแตกไฟล์ และตรวจสอบเช็กซัม

นอกจากตัวสร้างแล้ว tfg ยังมีเครื่องมือเล็กๆ สำหรับไฟล์ที่คุณมีอยู่แล้ว: ไฟล์บีบอัดแตกได้อย่างปลอดภัยหรือไม่ และไฟล์หนึ่งหรือทั้งโฟลเดอร์ยังตรงกับที่เช็กซัมบอกหรือไม่ เครื่องมือเหล่านี้ทำงานบนเครื่องของคุณ ไม่ต้องอัปโหลดและไม่ต้องมีบัญชี

คำตอบสั้นๆ

tfg tool archive-scan download.zip อ่านไฟล์บีบอัดโดยไม่แตกอะไรออกมาเลย และจบด้วยรหัส 0 เมื่อปลอดภัย หรือรหัส 7 พร้อมรายการสิ่งที่พบ tfg tool checksum setup.exe --expected <sum> บอกว่าไฟล์ตรงกับเช็กซัมที่หน้าดาวน์โหลดให้มาหรือไม่

ไฟล์บีบอัด

ไฟล์บีบอัดนี้แตกได้อย่างปลอดภัยไหม - zip slip และ zip bomb

archive-scan ดูข้างในไฟล์ ZIP, TAR, TAR.GZ หรือ gzip โดยไม่เขียนอะไรลงดิสก์ และบอกว่าการแตกไฟล์นั้นปลอดภัยหรือไม่ โดยรายงาน:

  • รายการข้างในที่จะถูกเขียนออกนอกโฟลเดอร์ ซึ่งเป็นกับดักที่เรียกว่า zip slip
  • ลิงก์ อุปกรณ์ หรือสองชื่อที่จะไปลงที่ไฟล์เดียวกัน
  • ชื่อที่ระบบใดระบบหนึ่งเขียนไม่ได้
  • รายการข้างในที่สร้างมาให้ระเบิดเมื่อแตกไฟล์ ซึ่งเป็นกับดักที่เรียกว่า zip bomb
  • รายการข้างในที่เสียหาย

ไฟล์บีบอัดที่อยู่ในไฟล์บีบอัด เช่น ZIP ใน ZIP หรือ DOCX ใน TAR จะถูกอ่านแบบเดียวกันในหน่วยความจำ ลึกได้ถึง 16 ชั้น กับดักในไฟล์ใดไฟล์หนึ่งก็คือกับดักของทั้งไฟล์ เพราะโปรแกรมที่แตกทุกอย่างก็จะแตกไฟล์เหล่านั้นด้วย 

tfg tool archive-scan upload.zip
tfg tool archive-scan backup.tar.gz --unpacked_limit 500mb

--unpacked_limit รายงานไฟล์บีบอัดที่แตกออกมาแล้วใหญ่เกินกว่าที่คุณอนุญาตด้วย เมื่อปลอดภัยจะจบด้วยรหัส 0 และเมื่อพบสิ่งใดจะจบด้วยรหัส 7 ไปป์ไลน์จึงหยุดตรงนั้นได้

ไฟล์เดียว

ไฟล์นี้ใช่ไฟล์ที่มันอ้างว่าเป็นหรือไม่

checksum คำนวณเช็กซัมของไฟล์ และเมื่อได้รับค่าที่จะเทียบ ก็จะบอกว่าตรงกันหรือไม่ รองรับ md5, sha1, sha256, sha512 และ crc32 โดยใช้ sha256 ถ้าคุณไม่ได้ระบุ และรู้ว่าค่าที่ได้รับเป็นแบบไหนจากความยาวของค่านั้น 

tfg tool checksum installer.msi
tfg tool checksum installer.msi --expected 9f86d081884c7d659a2feaa0c55ad015a3bf4f1b2b0b822cd15d6c15b0f00a08

เช็กซัมที่ไม่ตรงกันจะจบด้วยรหัส 7 เครื่องมือนี้ตอบคำถามเดียวกับ Get-FileHash บน Windows หรือ sha256sum บน Linux แต่เปรียบเทียบให้คุณเสร็จในตัว

ทั้งโฟลเดอร์

มีอะไรในโฟลเดอร์นี้เปลี่ยนไปหรือไม่

checksum-write เขียนเช็กซัมของทุกไฟล์ในโฟลเดอร์ลงใน SHA256SUMS ข้างๆ ไฟล์เหล่านั้น เป็นไบต์เดียวกับที่ sha256sum เขียน และไม่เขียนทับไฟล์ที่มีอยู่แล้ว ภายหลัง checksum-check จะตรวจทุกไฟล์ที่ SHA256SUMS ระบุไว้ 

tfg tool checksum-write ./fixtures
tfg tool checksum-check ./fixtures/SHA256SUMS

ไฟล์ที่ไม่ได้ระบุไว้จะไม่ถูกตรวจ เหมือน sha256sum -c และพาธที่ออกนอกโฟลเดอร์จะถูกปฏิเสธแทนที่จะถูกอ่าน ไฟล์ตัวอย่าง มาพร้อม SHA256SUMS ที่คุณตรวจด้วยวิธีนี้ได้

ถัดไป

จากตรงนี้ไปไหนต่อ

  • กรณีทดสอบการอัปโหลดไฟล์ วางการตรวจไฟล์บีบอัดไว้ร่วมกับกรณีอื่นๆ ของการอัปโหลด
  • เอกสาร มีทุกคำสั่งและทุกรหัสออก
