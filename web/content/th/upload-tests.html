กรณีทดสอบการอัปโหลดไฟล์ พร้อมไฟล์สำหรับรันทดสอบ

รายการตรวจสอบกรณีทดสอบสำหรับการอัปโหลดไฟล์ ตั้งแต่ขีดจำกัดขนาดไปจนถึงชื่อไฟล์ที่พยายามออกไปนอกโฟลเดอร์ของตัวเอง ทุกกรณีระบุไฟล์ที่ใช้ทดสอบและสิ่งที่ระบบของคุณควรทำกับไฟล์นั้น รายการนี้จึงรันได้จริง ไม่ใช่แค่อ่าน

ทั้งรายการในคำสั่งเดียว

tfg generate --preset upload-validation --limit 10mb --allow jpg,png,pdf --out ./upload เขียนไฟล์สำหรับเกือบทุกกรณีด้านล่าง พร้อมแมนิเฟสต์ที่บอกว่าควรเกิดอะไรขึ้นกับแต่ละไฟล์ ใส่ขีดจำกัดและชนิดไฟล์ที่ฟอร์มของคุณประกาศไว้

accept หมายความว่าระบบของคุณควรรับไฟล์ และ reject หมายความว่าควรปฏิเสธพร้อมข้อความที่ชัดเจน unspecified หมายความว่าคำตอบไหนก็ถูกได้ จึงควรจดไว้ว่าระบบของคุณตั้งใจแบบไหน แล้วตรวจว่ามันทำแบบนั้นทุกครั้ง คำที่ตามหลังผลลัพธ์คือเหตุผลที่แมนิเฟสต์ให้ไว้

ต่ำกว่าขีดจำกัดหนึ่งไบต์10mb_under_1b.jpgaccept
เท่ากับขีดจำกัดพอดี10mb_at_limit.jpgaccept
เกินขีดจำกัดหนึ่งไบต์10mb_over_1b.jpgreject size_limit
สองเท่าของขีดจำกัด เพื่อดูว่าเซิร์ฟเวอร์หยุดอ่านตั้งแต่เนิ่นๆ แทนที่จะรับทั้งไฟล์เข้าหน่วยความจำ10mb_far_over_2x.jpgreject size_limit
ไฟล์ว่างขนาด 0 ไบต์empty.jpgunspecified size_zero

สองกรณีที่ขีดจำกัดผิดบ่อยที่สุดคือขีดจำกัดที่ตรวจเฉพาะในเบราว์เซอร์ และขีดจำกัดที่นับเป็น MB ขณะที่โค้ดนับเป็น MiB พรีเซ็ต size-boundaries วางไฟล์ไว้ทุกระยะจากขีดจำกัดที่คุณเลือก ทั้งหนึ่งไบต์ หนึ่งกิโลไบต์ และหนึ่งเมกะไบต์ทั้งสองฝั่ง

ชนิดไฟล์

ฟอร์มรับชนิดที่ควรรับและปฏิเสธชนิดที่เหลือหรือไม่

กรณีทดสอบไฟล์ผลที่คาดหวัง
ทุกชนิดที่ฟอร์มรับ เป็นไฟล์จริงของชนิดนั้นallowed_jpg.jpg, allowed_png.png, allowed_pdf.pdfaccept
ชนิดที่ฟอร์มไม่รับdenied.svg, denied.html, denied.exe, denied.shreject extension_rule
นามสกุลบอกชนิดหนึ่งแต่เนื้อหาเป็นอีกชนิด เช่น PDF ที่ตั้งชื่อเป็น .jpgpdf_as_jpg.jpg, png_as_pdf.pdf, jpg_as_png.pngreject mime_mismatch
สองนามสกุล และนามสกุลสุดท้ายไม่ได้รับอนุญาตinvoice.jpg.exereject extension_rule
ไม่มีนามสกุลเลยinvoiceunspecified extension_rule
นามสกุลเป็นตัวพิมพ์ใหญ่PHOTO.JPGunspecified extension_rule

ไฟล์ SVG หรือ HTML ที่ถูกเข้าใจว่าเป็นรูปภาพหรือข้อความธรรมดาเป็นวิธีหนึ่งในการลอบส่งสคริปต์ผ่านฟอร์ม จึงอยู่ในรายการชนิดที่ต้องปฏิเสธ เว้นแต่ฟอร์มของคุณตั้งใจจะรับไฟล์เหล่านี้

เนื้อหา

ระบบเปิดไฟล์ดู หรือดูแค่ชื่อไฟล์

กรณีทดสอบไฟล์ผลที่คาดหวัง
ไฟล์ที่ถูกตัดสั้น แบบที่การอัปโหลดที่ถูกขัดจังหวะทิ้งไว้corrupt-truncate.pdfreject content_malformed
ไฟล์ที่ไบต์แรกๆ เป็นศูนย์ จึงไม่มีอะไรบอกว่ามันคือไฟล์อะไรcorrupt-zero-head.pngreject content_malformed
ไฟล์เล็กที่สุดที่รูปแบบยอมให้ ถูกต้องและเล็กมากtfg generate --preset empty-and-minimalaccept

ไฟล์ที่มีแค่ชื่อถูกและขนาดถูกจะผ่านทุกการตรวจที่ไม่เคยเปิดไฟล์ดู ไฟล์ตัวอย่างที่เสียหาย มีทั้ง PDF, Word, Excel, PowerPoint, JPG, PNG, MP4 และ ZIP และ ไฟล์ทดสอบที่เสียหาย อธิบายวิธีสร้างไฟล์แบบนี้ในทุกรูปแบบและทุกขนาด

ไฟล์กลับมาด้วยชื่อที่ได้รับไปหรือไม่

กรณีทดสอบไฟล์ผลที่คาดหวัง
ช่องว่างและวงเล็บmy report (final) v2.jpgaccept
ตัวอักษรนอก ASCII และอีโมจิwiadomość_日本語_🎉.jpgunspecified filename_invalid
ชื่อยาวเกิน 200 อักขระaaa...aaa.jpgunspecified filename_too_long
ชื่อที่ปีนออกนอกโฟลเดอร์ของตัวเอง ../ หรือ ..\climbing_name.jpg อัปโหลดด้วยชื่อ ../tfg_climbed_out.jpgunspecified filename_traversal
พาธสัมบูรณ์ บน Linux หรือ Windowsabsolute_name.jpg อัปโหลดด้วยชื่อ /tmp/tfg_climbed_out.jpgunspecified filename_traversal

ชื่อที่มีพาธอยู่ข้างในบันทึกลงดิสก์ไม่ได้ ไฟล์จึงใช้ชื่อธรรมดา และแมนิเฟสต์บอกว่าต้องอัปโหลดด้วยชื่ออะไร การรับไฟล์แล้วเก็บไว้แค่ส่วนสุดท้ายของชื่อเป็นคำตอบที่ดี การเขียนไฟล์ออกนอกโฟลเดอร์อัปโหลดคือข้อบกพร่องที่กรณีนี้มีไว้หา พรีเซ็ต filename-handling มีชื่ออีกมาก: ตัวอักษรหน้าตาคล้ายกัน อักขระที่มองไม่เห็น ชื่อที่ Windows สงวนไว้ และความยาวที่นับเป็นไบต์

ปริมาณและไฟล์บีบอัด

จะเกิดอะไรขึ้นกับไฟล์จำนวนมาก หรือไฟล์ที่บรรจุไฟล์จำนวนมาก

กรณีทดสอบไฟล์ผลที่คาดหวัง
ห้าสิบไฟล์ในการอัปโหลดครั้งเดียวbulk_0001.jpg ถึง bulk_0050.jpgaccept
ZIP ที่บรรจุเอกสาร 200 ฉบับจริงๆtfg generate --format zip --size 5mb --set entries=200 --set entry_format=pdfaccept
ไฟล์บีบอัดที่ระบบของคุณแตกไฟล์ ซึ่งตรวจหา zip slip และ zip bomb ก่อนtfg tool archive-scan upload.zipปลอดภัย หรือสิ่งที่พบ

--bulk กำหนดว่าการอัปโหลดเป็นกลุ่มมีกี่ไฟล์ ได้สูงสุดหนึ่งหมื่นไฟล์ เครื่องมือ อธิบายว่าการตรวจไฟล์บีบอัดมองหาอะไรบ้าง

ในการทดสอบ

รันรายการเป็นการทดสอบ

แมนิเฟสต์เก็บผลที่คาดหวังของทุกไฟล์และชื่อที่ใช้อัปโหลด ลูปเดียวจึงรันทั้งรายการได้: 

import json, os

directory = "upload"
manifest = json.load(open(os.path.join(directory, "manifest.json")))

for entry in manifest["files"]:
    outcome = entry["expected"]["outcome"]
    if outcome == "unspecified":
        continue
    name = entry.get("send_as", entry["name"])
    response = upload(os.path.join(directory, entry["path"]), name)
    assert response.ok == (outcome == "accept"), name

ไฟล์ที่มีป้าย unspecified ถูกข้ามไปตรงนี้ เพราะคำตอบของไฟล์เหล่านั้นคือนโยบายของคุณเอง ตัดสินใจ แล้วเขียนลงในสูตรด้วย expected แล้วลูปจะตรวจไฟล์เหล่านั้นด้วย ไฟล์ทดสอบใน CI รันสิ่งนี้ในไปป์ไลน์
